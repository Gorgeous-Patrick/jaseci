- **Native walker dependency inspection**: Opt-in RC walker speculation now inspects object accesses before launching abilities, defers conflicting work, and retains completed results across batches while preserving traversal-order commits. Multi-hop queries and resolvable helpers reuse Native lowering. The new `walker_dependency_inspection` setting defaults to true and can be disabled for comparison; `walker_speculation` remains off by default.
- **Experimental PTX output**: `jac build <file> --as ptx --gpu-entry <function-or-walker>` emits NVIDIA batch kernels for runtime-free float64/bool functions or restricted read-only chain walkers. Chain kernels follow packed successor arrays, keep each walker's state private, and report invalid indices and cycles. Unsupported operations are compile errors. The build command emits artifacts without executing them; CPU checks and PTX emission do not establish GPU execution correctness or performance.
- **Experimental CUDA walker runtime**: `GpuWalkerRuntime.run_walkers(walkers, starts)` accepts actual homogeneous Jac walker instances, packs private read-only chain graphs into shared SoA storage, and publishes scalar results after successful CUDA execution. Two aligned device arenas grow and are reused across batches; host-only ABI and lifecycle tests do not substitute for NVIDIA device validation.
- **Integer GPU chain walkers**: Chain walkers now support signed int64 fields, checked addition/subtraction/multiplication, signed modulo, numeric comparisons, and guarded updates with `if`/`elif`/`else`. The new `EvenSum` example sums even node values across 1,000 walkers. Integer inputs and outputs retain exact precision; overflow or modulo by zero rejects publication of the entire batch.
- **Experimental CSR GPU walkers**: `GpuWalkerRuntime(..., graph_format="csr")` and `jac build --as ptx --gpu-graph-format csr` support the existing numeric walker subset on branching, shared read-only graphs. Device FIFO queues preserve visit order and repeated arrivals; configurable queue and visit limits reject incomplete batches without publishing walker fields. The 1,000-walker CSR example checks results against serial Jac. CSR remains a provisional storage experiment, alongside the unchanged default chain format.
- **GPU node field columns**: CUDA walkers can read multiple numeric node fields and fixed, owned nested objects. Each numeric leaf is packed into an aligned SoA column in both chain and experimental CSR modes; cross-node nested object sharing is rejected before launch. All leaves currently match the walker's int64 or float64 state type.
- **GPU walker field columns**: Chain and CSR walkers can update multiple numeric state fields, including owned nested objects, in Jac statement order. Each leaf has separate initial/result SoA columns and private thread state. All fields are published only after the entire batch succeeds and host state remains unchanged. Mutable nested state cannot be shared between paths, walkers, or graph nodes. The `walker_fields_run.jac` example checks four fields for 1,000 walkers against serial Jac; mixed int/float fields remain unsupported.
- **Numeric GPU walker reports**: Chain and CSR walkers support ordered int64/float64 `report` expressions, including conditional reports. Bounded report storage interleaves each report slot across walker lanes. Successful batches replace `walker.reports` and expose `result.reports`; capacity overflow or other execution failures publish neither state nor reports. Report kernels use v4 manifests, while existing kernels retain their ABI.
- **Boolean GPU walker fields and reports**: Chain and CSR walkers support boolean node and walker fields, short-circuit logical expressions, and typed boolean/numeric report streams.
