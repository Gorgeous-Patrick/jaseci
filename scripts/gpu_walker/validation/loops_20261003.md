# Device loop correctness validation (2026-10-03)

The shared chain/CSR body lowering emits LLVM loop header/body/exit blocks,
loop-carried PHIs and backedges. Dynamic bounds come from node values and scalar
locals. This implementation does not unroll source loops in the compiler.

| Validation | Result | Execution evidence |
| --- | --- | --- |
| `test_loops.LoopTests` + `test_reports` | 23 tests, 22 passed, 1 CUDA-only test skipped | LLVM host JIT and mock CUDA driver; serial Jac references |
| `test_state_fields` + `test_csr` + `test_booleans` | 22 passed | LLVM host JIT/mock runtime and serial Jac references |
| `jac test jac/tests/compiler/backends/native/test_ptx_walker.jac` | 9 passed | LLVM verification, NVPTX emission, backedge and ABI checks |
| CUDA-enabled loop tests and two loop/report tests | 15 passed | Real CUDA session launches emitted PTX and compares outputs/statuses with host JIT and serial Jac |
| CLI builds of `loops.jac`, chain and CSR | Both passed | `.ptx`, `.gpu.ll` and manifest emitted |

| `jac run jac/examples/gpu/loops_run.jac` | 64 walker results matched; `GPU executed: True` | Real NVIDIA GeForce RTX 3090 |

The CUDA device was NVIDIA GeForce RTX 3090, driver 595.71.05 (driver reports
CUDA 13.2). LLVM was 20.1.8, supplied by the existing llvmlite-compatible LLVM
shim selected with `JAC_LLVM_SHIM`; this checkout lacked `libjacllvm.so`.
Missing typeshed stdlib stubs were supplied from the existing local Pylance
installation. These environment repairs are not tracked source changes.
Sandbox device isolation initially hid `/dev/nvidia*`; real CUDA checks and
the CUDA example ran outside the sandbox after approval. No real-device result
is inferred from the mock driver or host JIT.

Coverage includes dynamic and nested ranges, bounds depending on the outer
induction variable, negative steps, zero iterations, bounds evaluated once,
int64 boundary termination, while conditions, branch-carried values, float and
boolean locals, short-circuit conditions, sequential local/field updates,
reports in loops, CSR repeated arrivals, report capacity failures, arithmetic
errors, and preservation of host state/reports on failed batches. Existing
integer, boolean, multi-field and CSR traversal behavior is covered separately.

An initial broad run found an obsolete negative test that rejected all scalar
locals. It now rejects a newly declared branch local, which remains unsupported.
Both the corrected regression suite and the final loop/report suite passed.
An initial IR string assertion expected quoted block labels; LLVM canonicalizes
these labels without quotes. The test now checks the canonical backedge form,
and all nine compiler checks passed on rerun.

Reproduce from the repository root with a working Jac LLVM shim:

```bash
export PYTHONPATH=jac:scripts/gpu_walker
python -m unittest test_loops.LoopTests test_reports -v
python -m unittest test_state_fields test_csr test_booleans -v
jac test jac/tests/compiler/backends/native/test_ptx_walker.jac
JAC_GPU_TEST_CUDA=1 python -m unittest test_loops.LoopTests \
  test_reports.ReportTests.test_device_loops_preserve_reports_locals_and_csr_arrivals \
  test_reports.ReportTests.test_float_boolean_locals_and_short_circuit_loop_condition -v
jac run jac/examples/gpu/loops_run.jac
```

Range accepts one/two dynamic int64 bounds and an optional nonzero literal
int64 step. Targets are fresh read-only locals visible inside the loop. Other
scalar locals must be initialized at ability top level, with a fixed type.
Nested loops and conditionals are supported; loop-else, break/continue, inner
visit, other iterables, dynamic steps, and inner first declarations are rejected.
Loops must terminate; graph traversal limits do not bound inner iterations.
No device buffers, complete matmul, thread cooperation, or performance claims
are included.
